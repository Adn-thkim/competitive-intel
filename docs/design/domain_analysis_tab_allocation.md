# 도메인 분석 탭 — 콘텐츠 배치안 (v1.0)

- 작성 기준일: 2026-09-09
- 대상: `docs/mockups/domain_analysis_tab.html` (v0.3) 에 작성된 D1~D9 전 항목
- 목적: 도메인 분석 / 비교 매트릭스 / 종합 리포트 3개 산출물의 경계를 확정하고, 각 항목의 소속을 결정한다.

---

## 1. 배치 판정 기준

새 항목이 추가될 때마다 흔들리지 않도록, 항목별 판단이 아니라 **기준 3개를 순서대로 통과**시킨다.

| # | 질문 | Yes → 소속 |
|---|---|---|
| 1 | 상품마다 **값이 다른가** (셀에 채울 수 있는가) | 비교 매트릭스 |
| 2 | 특정 상품이 아니라 **시장·규칙에 대한 진술**인가 | 도메인 분석 |
| 3 | "그래서 어떻게 해야 하는가"로 이어지는 **판단**인가 | 종합 리포트 |

### 한 줄 정의

- **도메인 분석** — 매트릭스를 *읽는 법*을 정의한다 (정의·단위·등급·변별력)
- **비교 매트릭스** — *값*을 담는다
- **종합 리포트** — *판단*을 담는다

## 2. 항목별 판정

### D1 · 도메인 정의 & 경계

| 항목 | 판정 | 근거 |
|---|---|---|
| 도메인 정의 / 포함·제외 기준 | 도메인 유지 | 스코프 선언. 비교 대상 선정의 근거 |
| 별칭 매핑 (검색어 정규화) | 도메인 유지 | `query_intake` 단계용 메타데이터. 리포트 독자에게 무의미 |
| 사업자 유형 · 법적 형태 | → 매트릭스 | 상품별 값. 단 행이 아니라 **열 헤더 배지**로 (혜택 스펙이 아니라 전제) |
| 신뢰도 등급 | 도메인 유지 | D9 와 함께 관리 |

### D2 · 시장 구조

| 항목 | 판정 | 근거 |
|---|---|---|
| 시장 규모 · CR3 · 성장률 | 도메인 유지 | 상품별 값이 아닌 시장 전체 값 |
| 1위 점유율 45.3% | → 매트릭스 | 상품별 값. D7 기준 KPI 와 짝이 되는 정량 행 |
| 집계 불일치 경고 | → D9 로 통합 | 성격상 신뢰도 항목. 현재 D2 배치는 위치 오류 |

### D3 · 비즈니스 모델 & 전략적 의도

> 가장 많이 분해되어야 하는 섹션.

| 항목 | 판정 | 근거 |
|---|---|---|
| 용어 정의 (결제 관계 안/바깥) + 수도관·저수지 비유 | 도메인 유지 | 도메인 어휘. 매트릭스와 리포트가 공유하는 언어 |
| 회수 경로 표 4행 (인터체인지 / 재환전 / 국내전환 / 예수금) | → 매트릭스 | 전부 상품별 값. 도메인에 둘 이유 없음 |
| "결제 1건이 끝난 뒤 남는 것" 행 | → 리포트 | 4행을 종합한 서술. 셀에 담기 어려움 |
| 여행자 1명 시뮬레이션 (하나 vs 토스) | → 리포트 | 두 상품을 골라 비교한 해석 |
| "이 표에서 읽어야 할 것" 해석 박스 | → 리포트 | 명백한 판단 |
| 재환전 수수료의 이중 역할 (락인) | → 리포트 | 요율은 매트릭스 값, 락인 해석은 판단 |
| 전략적 의도 표 | 도메인 유지 | 아래 단서 참조 |

**단서 — 전략적 의도 표**
상품별 값이므로 기준 ① 로는 매트릭스이지만, 매트릭스에 올리면 "고객이 무엇을 받는가"라는 성격이 흐려진다.
도메인 유지를 권한다. 이것은 상품 스펙이 아니라 **사업자의 성격 규정**이며, 리포트가 이를 전제로 논리를 세운다.
단 **자사 행은 리포트가 직접 인용**해야 한다 (제언의 출발점이므로).

### D4 · 기능별 변경 이력

| 항목 | 판정 | 근거 |
|---|---|---|
| 이벤트 행 (날짜·상품·기능·방향·내용) | 도메인 유지 | 사실 레코드 |
| `last_changed_at` · `change_count_36m` · `volatility` | → 매트릭스 | 셀 파생 메타데이터. "혜택 변동성" 이라는 새 비교축 |
| `direction: "incident"` (2026-03-10 엔화 오류) | → 고객 반응 리포트 | 반응 데이터의 교락 변수로 격리 인식 필요 |
| 반기 요약문 | **분리 필요** | 아래 단서 참조 |

**단서 — 반기 요약문 분리**
현재 사실과 해석이 한 문단에 섞여 있다.

- 사실 → `fact_summary` (도메인 유지)
  예: "같은 5월에 ATM 을 유료화하고 예치 기능을 신설했다"
- 해석 → `implication` (리포트로 전달)
  예: "회수 경로를 결제 바깥으로 옮기는 작업이 시작된다"

### D5 · 경쟁축의 이동

| 항목 | 판정 | 근거 |
|---|---|---|
| 시기별 지배축 + 사망/활성 판정 | 도메인 유지 | 매트릭스 행의 변별력을 정하는 규칙 |
| `discriminating: true/false` 플래그 | → 매트릭스 | 각 행에 부여되는 속성 |
| "지금 무엇이 경쟁축인가" 의 함의 | → 리포트 | 어디에 투자할지의 근거 |

### D6 · 규제·제도 환경

| 항목 | 판정 | 근거 |
|---|---|---|
| 제도별 내용 · 유효기간 | 도메인 유지 | 시장의 규칙 |
| "특례 보유 여부" (하나 O / 토스 미확인) | → 매트릭스 | 상품별 값. 기능 차이의 원인을 매트릭스에서 즉시 확인 가능 |
| "토스도 특례 신청이 액션 옵션" | → 리포트 | 명백한 제언 |

### D7 · 도메인 KPI 정의

| 항목 | 판정 | 근거 |
|---|---|---|
| 기준 KPI 선언 · 제외 지표 · 채널 KPI 계층 | 도메인 유지 | 측정 규칙. 매트릭스 정량 행이 따라야 할 단위 정의 |
| 실제 점유율 수치 | → 매트릭스 | 값은 매트릭스, 규칙은 도메인 |

### D8 · 변곡점 워치리스트

| 항목 | 판정 | 근거 |
|---|---|---|
| 만료 일정 목록 (2026-09-30, 2026-12-31) | 도메인 유지 | 사실 |
| "시즌7 연장 여부가 회수 경로 구성을 바꾼다" | → 리포트 | 조건부 판단 |
| "2027년 1월이 변곡점" | → 리포트 | **언제 움직여야 하는가**에 대한 유일한 근거 |

### D9 · 데이터 신뢰도 & 갭

| 항목 | 판정 | 근거 |
|---|---|---|
| 추론 / 점검 필요 / 확인 불가 목록 | 도메인 유지 | 데이터 품질 선언 |
| 셀 단위 `confidence` | → 매트릭스 | 배지 |
| "결제 건당 금액 분포 없음 → 손익분기 영향 계산 불가" | **양쪽 모두** | 리포트에 한계 고지로 **복제 필수**. 없으면 리포트가 과잉 단정 |

## 4. 실행 전 결정이 필요한 사항

### 4-1. 매트릭스의 성격이 확장된다

회수 경로 4행을 올리면 매트릭스가 *"고객 관점 혜택 비교"* 에서 *"사업자 관점 수익 구조"* 까지 담게 된다.

→ 매트릭스에 **행 그룹 구분**을 둔다.

- 그룹 A: 고객이 받는 것 (환율우대, 결제 수수료, ATM, 통화 수, 라운지 …)
- 그룹 B: 사업자가 회수하는 것 (인터체인지, 재환전, 국내 전환, 예수금)

구분 없이 섞으면 독자가 "재환전 0%" 를 혜택으로만 읽고 락인 부재라는 이면을 놓친다.

### 4-2. 중복 위험

`재환전 수수료`, `국내 캐시백` 은 이미 `feature_table.columns` 에 존재할 가능성이 높다.
이관 전 현재 `feat_*` ID 목록을 확인해 매핑하지 않으면 같은 값이 두 행에 생긴다.

**선행 작업**: `feature_table.columns` 의 `feature_id` 전수 조사 → 이관 항목과의 매핑표 작성

### 4-3. 도메인 탭이 얇아진다

이관 후 도메인 탭에는 정의 · 규칙 · 타임라인만 남아 시각적으로 단조로워진다.
이는 역할이 명확해진 결과이므로 문제가 아니지만, **D4 타임라인을 탭의 중심으로 재배치**하는 편이 자연스럽다.

권장 순서: D1 (정의) → **D4 (타임라인, 중심)** → D5 (경쟁축) → D2 (시장 구조) → D3 (사업자 유형·전략적 의도) → D6 (규제) → D7 (KPI) → D8 (워치리스트) → D9 (신뢰도, 토글)

## 5. 스키마 반영 사항

```python
# state.py
domain_analysis: dict   # D1, D2, D3(축소), D4, D5, D6, D7, D8, D9
```

### 이관 항목에 부여할 태그

리포트 노드가 미구현인 동안 도메인 탭에 임시 보관할 경우, 항목마다 목적지를 태깅한다.

```json
{
  "target": "comparison_matrix" | "insight_report" | "reaction_insight" | "domain",
  "feature_id": "feat_fx_reconvert_fee",
  "inference": true,
  "evidence_type": ["financial", "behavioral", "statement"],
  "confidence": "confirmed" | "single_source" | "inferred" | "unverified"
}
```

- `feature_id` 는 매트릭스와 **동일 네임스페이스** 를 사용한다. 어긋나면 조인이 성립하지 않는다.
- `target` 이 `domain` 이 아닌 항목은 화면에서 숨기거나 "이관 예정" 배지로 표시한다.

## 6. 후속 과제

1. `feature_table.columns` 의 `feat_*` 전수 조사 → 중복 없는 이관 매핑표
2. D4 반기 요약을 `fact_summary` / `implication` 두 필드로 분리
3. 경쟁사 국내 혜택 조사 (현재 하나 · 신한만 1줄 요약, KB · 우리 · 트래블월렛 미조사)
4. `insight_report` 노드 구현 시 이관 항목 9건을 입력으로 배선
