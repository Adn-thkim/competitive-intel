# 인사이트 리포트 작성 규칙

트래블카드 경쟁 분석 · 최종 인사이트 리포트(v2)를 작성·수정할 때 적용하는 규칙.
리포트 본문에서 제거한 작업용 규칙을 여기에 모았다. 리포트에는 결론과 근거만 남기고,
어떻게 쓸 것인가는 이 문서가 담당한다.

작성 기준일 2026-09-10 · 대상 문서 `docs/mockups/domain_analysis_tab.html` 의 `pane-final2`

---

## 1. 수치 표기

### 1-1. 본문에서 감정 지수를 쓰지 않는다

감정 지수(net)는 **방향·강도·표본을 한 숫자로 압축**한다. 압축되는 순간 표본이 사라져서
2건의 `+1.00`과 57건의 `−0.05`가 지면에서 같은 무게로 보인다. 또 소수점 둘째 자리는
없는 정밀도를 주장한다 — 극성과 강도는 LLM 판정값이다.

- **본문 서술은 방향과 건수로만 한다.** 예: "57건 중 긍정 23 · 부정 23으로 반반 갈린다"
- **값은 표 안에만 둔다.** 표에서는 긍/부/중 건수를 같은 행에 병기한다
- 두 지수의 차이(격차)는 오차가 두 번 겹치므로 본문에서 쓰지 않는다

### 1-2. 표본 하한 4단계

| 관측 건수 | 허용 서술 |
|---|---|
| 20건 이상 | 방향 + 비율 서술 가능 |
| 10 ~ 19건 | 방향만. 비율은 표에만 |
| 5 ~ 9건 | "관측이 적다"를 함께 쓰고 값 단독 사용 금지 |
| 5건 미만 | 값 금지. **건수만** |

이 규칙은 서술을 약하게 만들지 않는다. 신뢰성 관점은 5건이라 값을 쓸 수 없지만
**"5건 중 긍정이 0건"**이 `−0.91`보다 정직하면서 더 강한 진술이다.

현재 이 규칙에 걸리는 것: 앱 이용(2건) · 국내결제(1건) · 혜택 관점(3건) ·
신뢰성 관점(5건) · ATM 세그먼트 분해(각 4건).

### 1-3. %p 표기를 쓰지 않는 이유

지수는 이미 비율이므로 `×100`이면 퍼센트가 되고, 의미상으로는 **긍정률 − 부정률**이니
`%p`가 단위로는 오히려 정확하다. 그런데 현재 값에는 **강도 가중이 들어 있어** 순수한
건수 비율이 아니다. `%p`로 쓰면 독자는 건수 비율로 읽고 실제와 어긋난다.

ATM(자사)이 그 예다.

| 계산 방식 | 값 |
|---|---|
| 강도 가중 | −0.093 |
| 순수 건수 비율 | **0.000** (긍정 10 · 부정 10) |

차이는 **부정 의견의 강도가 긍정보다 높다**는 정보에서 온다. 이 정보를 버리고 건수 비율로
가면 `%p`가 정확해지지만, *"절대 비추"*와 *"별로임"*이 같은 무게가 된다.
현재는 강도 가중을 유지하므로 `%p`를 쓰지 않고, 표의 열 이름도 "지수"로 둔다.

### 1-4. 채널 가중을 쓰지 않는다

`reaction_insight_node.CHANNEL_WEIGHTS`(유튜브 1.0 · 커뮤니티 0.9)는 리포트 집계에서 제외했다.

- 68개 셀 중 20개가 단일 채널이라 가중이 **수식상 상쇄**된다
- 남은 48개 셀에서도 최대 변동 0.048 · 평균 0.009로 **판정을 바꾼 사례가 없다**
- 실제 채널 간 격차는 ±1.0에 달해 0.1 폭 가중으로 대표할 수 없다
- 근거가 코드 주석(*"사용자 확정 2026-06-06"*) 외에 문서화되어 있지 않다

**대신 채널을 분리해 함께 제시한다.** 가중이 감추고 있던 것이 이때 드러난다 —
자사는 검토 담론과 사용 경험 담론의 평가 방향이 반대이고, 하나는 그 반대다.

개발 재개 시 코드 변경: `CHANNEL_WEIGHTS`를 전 채널 1.0으로 두고 `build_aspect_matrix`에
채널별 분리 집계를 추가한다. `select_top_quotes`의 정렬 tie-break 용도는 결정론적 순서
보장이 목적이므로 남겨도 무해하다.

## 2. 리포트에 넣지 않는 것

다음은 작업 과정의 산물이므로 리포트 본문에 넣지 않는다.

- **수치 표기 규칙 자체** — 이 문서가 담당한다
- **데이터 출처 경로·노드명·캐시 키** (`reaction_report_node`, `cluster 998c7552`, `units 543` 등).
  단 **표본 크기와 기준일은 남긴다** — 해석에 필요한 정보다
- **파이프라인 단계명** (gate / prescreen / extract / cluster)
- **재집계 방법론의 세부** — 결론에 영향을 준 경우에만 한계 항목으로 한 줄 남긴다

## 3. 리포트에 반드시 남기는 것

- **표본 크기** — 모든 수치 옆에
- **추론 표시** — 관측이 아닌 해석에는 `추론` 배지
- **원인 귀속을 하지 않았다는 사실** — 인과가 보도·측정되지 않은 경우 명시
- **본 분석의 판단으로 분류한 항목** — 예: 부정 29건의 원인 분류는 산출물 라벨이 아니라 본 분석의 판단
- **검토 범위** — 원문을 전량 읽은 범위와 라벨에 의존한 범위를 구분

## 4. 서술 원칙

### 4-1. 비유는 학습 장치이므로 인사이트 리포트에 넣지 않는다

임원 독자는 은행·카드사 수익 구조를 이미 안다. 비유는 정보를 더하지 않고 정확도를 희생하며,
반박 가능한 표면을 만든다. 개념 정의가 필요한 곳(도메인 분석 탭 D3)에만 둔다.

### 4-2. 가설 제기와 증명 설계는 리포트의 형식이 아니다

"가설 → 지지 증거 → 반증 → 미배제 대안"은 분석 노트의 형식이다.
리포트에는 **관측 사실에 근거한 판정**과 **그 판정으로 무엇을 할 것인가**를 쓴다.
확정되지 않은 것은 `작업 전제`로 명시하고, 확인 범위의 한계를 함께 적는다.

### 4-3. 기회는 교집합에서만 나온다

**경쟁사가 하지 않는 것 × 고객이 불편해하는 것 × 우리가 할 수 있는 것.**
셋 중 하나라도 빠지면 기회가 아니라 아이디어다. 교집합이 성립하지 않는 항목은
`방어` 또는 `선결 조건`으로 분류하고, 기회 목록에 섞지 않는다.

### 4-4. 표만 두지 않는다

표 하나만 두면 독자가 해석을 전담한다. 표 앞에 **무엇을 볼 것인가**를 한 줄,
표 뒤에 **그래서 무엇인가**를 한 줄 붙인다.

### 4-5. 액션은 비용 축으로 배열한다

저비용 액션을 앞에 두고, 지출이 필요한 액션은 잔여 격차 측정 뒤로 미룬다.
각 액션에 **비용 수준**을 표기해 우선순위 판단이 표에서 끝나게 한다.

### 4-6. 조건을 늘리는 개선은 불확실성 제거와 충돌하는지 먼저 본다

질문의 다수가 조건 확인형이라면, 조건을 하나 늘리는 것은 확인해야 할 것을 하나 늘리는 것이다.
세그먼트별 조건 설계·구간 신설·예외 추가는 이 충돌을 검토한 뒤에만 권고한다.

## 5. 데이터 사용 시 주의

### 5-1. 질문은 유형 라벨만 보지 말고 원문을 읽는다

라벨만 보면 놓치는 층이 있다. 실제로 정정 2건이 나왔다.

- 문제 해결 8건 중 3건은 실제로 **정보 충돌 해소 요청**이었다
- 비용 6건은 전부 **가격 정보 부재**였고 가격 불만은 없었다

### 5-2. 도메인 경계 밖 개념이 섞인다

*"연회비는 있나요?"*는 하나 트래블로그·카드 발급에 귀속됐으나 **연회비는 신용카드 개념**이다.
수집 오류는 아니지만 체크카드 도메인의 근거로 쓸 수 없다. 예시 인용 전에 개념이
도메인 안에 있는지 확인한다.

### 5-3. 정책 변경 기간의 반응은 분리한다

자사 유튜브 부정에는 유료화 기간(2026-04~08) 반응이 섞여 있다 —
*"너프됨"*·*"반토막"*·*"건당 수수료"*. 8월 원복 이후만 분리하지 않으면
현재 조건에 대한 평가로 오독된다.

### 5-4. 어법 패턴 검색 결과는 하한으로 표기한다

"확인 요청형 23건"은 *"~아닌가요/맞나요/건가요"* 계열만 잡은 것이다.
*"~까요?"* 형태가 빠져 실제보다 과소집계다.

### 5-5. 쓰지 않기로 한 데이터

- **고객 개선 제안(`is_suggestion`)** — 원문이 단편적이고, cluster·aspect 부여 과정에서
  제안이 축으로 설정되지 않아 데이터가 온전하지 않다. 추출 축을 추가한 뒤 재수집해야 한다
- **제외된 175건** (비트래블카드 80 · 기타 트래블카드 64 · 미귀속 31) — 비교 범위 밖 대안
  (현금·타행 앱·간편결제)이 여기 있다. 도메인 정의(D1)의 경쟁 범위를 다시 열지 결정이 필요하다

## 6. 판정을 바꿀 때

판정이 뒤집히면 **이전 판을 지우지 않는다.** 탭을 분기해 이전 판을 보존하고
도메인 분석 탭 D9(변경 이력)에 무엇이 왜 바뀌었는지 적는다.

지금까지 뒤집힌 판정:

| 항목 | 이전 | 이후 | 계기 |
|---|---|---|---|
| 앱 이용 | 자사 우위 | 하나와 동률(각 2건) | 정식 산출물로 재집계 |
| 재환전 0% | 인식되지 않는 우위 | 이미 작동하는 우위 | 산출물 긍정 근거에 직접 인용됨 |
| 해외결제 | 접전 | 열위(부정률 46% vs 21%) | 정식 산출물 재집계 |
| ATM 최우선 액션 | 한도 복원 | 정보·실행 개선, 한도는 현 수준 유지 | 부정·질문 원문 분해 |
| 1순위 기회 | 혜택 동등화 | 불확실성 제거 | 질문 170건의 성격 분석 |
